# Remaining milestones and acceptance gates

The original [product requirements](PRODUCT-REQUIREMENTS.zh-CN.md) remain the final target. This alpha is not a substitute for them.

1. **Finish physical input acceptance first.** Install/verify a user-approved signed USB/IP prerequisite on a controlled Windows host; validate the chosen upstream VIIPER version, host physical pad and remote virtual pad through independent XInput and an actual local two-player game. Test all analog travel, disconnect/revoke and game-generated rumble. Validate Windows and macOS guests separately. Any OS player-index mismatch must remain visible.
2. **Harden the input release.** Add multiple guest/controller lifecycle, observed per-device report rates, robust player reassignment and native macOS event-loop acceptance. Exercise suspend/resume, process crash and external VIIPER timeout. The four-slot core is not four-guest session support.
3. **Ship real native 1080p60 media.** Windows WGC + D3D11 / Desktop Duplication fallback; NVENC/AMF/QSV capability detection; H.264 first, conditionally HEVC/AV1; native decoder and GPU swap-chain presentation independent of WebView frames. Measure capture/encode/network/decode/present and drop stale frames. Add WASAPI loopback, Opus 48 kHz and bounded synchronized playback. Do not create empty media crates or a screenshot-stream mock.
4. **Complete remote play.** Combine authorized input and real media, conditional keyboard/mouse control, monitor selection, bandwidth/loss/jitter metrics, explicit stop/kick and reproducible two-network direct/TURN tests. Run 30-minute physical play tests.
5. **Optimize from measurements.** Validate sustained 1080p60 before 120/144 FPS, then 1440p/4K and HDR capability gates; adaptive bitrate/congestion control, frame pacing and ICE restart/reconnect. No setting value is accepted as an achieved FPS.
6. **macOS host.** ScreenCaptureKit / VideoToolbox / Metal / native audio; entitled CoreHID or a properly signed system extension only after independent device/game compatibility tests. Do not substitute keyboard mappings for a controller.
7. **Production distribution.** Windows application signing, Apple signing/notarization and tested installs on both Mac architectures. Generate and securely retain update-signing keys, publish signed manifests and enable the updater only when signature verification can be enforced. Driver signing remains a separate upstream/in-house gate.
